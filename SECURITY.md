# Responsible vulnerability reporting

**Status:** Early development, not a production service or an accredited private-intake system.

Do not submit passwords, encryption keys, personal testimony, witness identities, personal medical information, or sensitive case records to public GitHub issues or this project's demo forms.

For a security finding, use the repository's private security-reporting channel **if GitHub private vulnerability reporting is enabled**; otherwise contact the repository owner through a pre-existing trusted private channel to arrange a secure disclosure method. Do not assume GitHub issue comments are private. Report a sanitized impact description first.

The team must acknowledge, triage, assess impact and patch under documented roles and incident-response controls before launching private features. Consult the canonical plan §7 and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). E2EESA certification is **not** claimed for this codebase.
